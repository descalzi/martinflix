# First-run installer

Start with a Linux host and an account that can run Docker Engine and Docker Compose. If Docker is missing, install [Docker Engine and the Compose plugin](https://docs.docker.com/engine/install/) for your distribution and confirm `docker info` works as your normal user. Nothing else is needed: setup, the dashboard and the controller all run from the MartinFlix image, `ghcr.io/descalzi/martinflix`.

Run:

```sh
docker run --rm -it --pull always -v /var/run/docker.sock:/var/run/docker.sock -v "$HOME:$HOME" -e HOME \
  ghcr.io/descalzi/martinflix:edge install --media-path /mnt/media --check
docker run --rm -it --pull always -v /var/run/docker.sock:/var/run/docker.sock -v "$HOME:$HOME" -e HOME \
  ghcr.io/descalzi/martinflix:edge install --media-path /mnt/media
```

`docker run … install` starts setup in two steps. The first container sees only the Docker socket and your home folder; it works out which other folders setup needs (the media folder, the backup folder, a state directory outside your home) and starts the installer in a second container with exactly those folders at the same paths, the VM’s network, and your account. Paths must match the VM’s because Docker resolves every folder in the Compose files on the VM. `update` in place of `install` updates an existing installation, and `reset` starts from scratch. In the rest of this guide, “run setup with `--flag`” means adding the flag to that command.

Replace `/mnt/media` with your media directory. New installations and resets need one, because Sonarr and Radarr file series and films there; installations made before this keep working without one until you add it.

The check verifies the Python and Linux environment, Docker Engine and Compose, access to the local engine, storage permissions, and service ports. It creates no directories, pulls no images, and starts no containers.

| If the check says… | What to do |
| --- | --- |
| Docker or Compose is missing | Follow the [Docker installation instructions](https://docs.docker.com/engine/install/) and rerun the check. |
| Docker Engine is unavailable | Follow the start command printed for your Docker installation, then run `docker info`. |
| Your user cannot access Docker | Follow [Docker’s Linux access setup](https://docs.docker.com/engine/install/linux-postinstall/), sign out and back in, and rerun the check as your normal user. |
| A port is already in use | Use the flag named in the error with a free port, such as `--dashboard-port 18765`. Keep that flag in your install command. |
| A directory is unwritable or has unexpected permissions | Choose a private, writable directory with `--state-dir`. |
| An image download or build fails | Check the VM’s internet connection and Docker storage, then rerun with the same options. Image downloads are checked during installation. |

New installs store app data in `~/.local/state/martinflix` by default. Rerunning an earlier install reuses its existing `~/.local/state/martinflix-first-run` directory and Docker project. Continue passing the same `--state-dir` for an existing custom path. It starts Sonarr and Radarr, waits for their health checks, reads the keys generated by the apps, and starts the dashboard with private copies of those keys. It checks that the dashboard can read both libraries. Fresh libraries appear empty until you add titles.

The installer adds Sonarr’s enabled **Bad Stuff** release profile from the reference setup. It excludes releases whose titles match `MeGusta`, `scr`, `exe`, or `ETHEL`. Setup also seeds Sonarr’s indexer defaults once, using a minimum age of 120 minutes and a maximum size of 3,000 MB. It preserves any existing nonzero values and leaves later edits in place.

Radarr gets **No OPUS** and **No HEVC**, both disabled to match the reference setup. You can enable either profile in Radarr to filter titles that match `Opus` or `HEVC` before download. Setup preserves existing release profiles with matching names in both apps.

New Radarr installations start with a maximum release size of 4,500 MB, an availability delay of 1 day, and an RSS sync interval of 120 minutes. Rerunning setup preserves your Radarr indexer settings.

The installer finishes with an **Open your dashboard** section. Sign in as `admin` using the temporary password shown by the command in that section. Sonarr, Radarr, Prowlarr, Transmission, and Bazarr use the username `admin` and the same temporary password. When you set your password on first sign-in or use **Change password** in the dashboard, MartinFlix updates every app, including the Transmission connection inside Sonarr, Radarr and Prowlarr. The apps need to be running. If one can’t be reached, the dashboard keeps its current password; submit the same new password again once the app is back. The dashboard stores the chosen password as a salted hash in the private `dashboard-auth` directory.

### Plex

Add `--enable-plex` (on by default in the wizard) to install Plex Media Server for your media directory. Plex runs on the host's network, as LinuxServer recommends, so TVs and phones on your LAN find it by themselves and it listens on port 32400 on every address of the VM. It reads the media directory but can't change it; Sonarr and Radarr own the files.

Just before Plex starts for the first time, setup asks for a **claim code**, which links the new server to your Plex account. Sign in at [plex.tv/claim](https://plex.tv/claim) and paste the code it shows; it lasts four minutes, so get it when setup asks. Once the server is claimed, setup:

- names the server **martinflix** (change it with `--plex-name`, for example on a test machine) and sets its pre-roll clips to every video in the image's `assets/preroll` folder, which setup copies into the state directory's `preroll` folder and Plex plays at random before films; both follow setup's options and each new version's clips;
- turns on **remote access** with automatic port mapping, so the router needs UPnP (eero has it on by default), and lets Plex use IPv6 where the network has it;
- applies MartinFlix's default server settings once: maintenance between 02:00 and 09:00, scanning when files change plus a daily low-priority scan, intro and credits markers during maintenance, cinema trailers, and DLNA, push notifications, crash reports and debug logging off;
- adds **Films** and **TV programmes** libraries over the media folders, with their advanced settings (only on a server with no libraries yet);
- connects the dashboard's Live page to Plex, with no token to copy.

If you skip the claim code, open Plex Web (`http://<VM address>:32400/web`) from a device on the same network to claim the server, then run setup's `update` to add the libraries and connect Live. If the VM has a GPU (`/dev/dri`), setup gives Plex access to it for hardware transcoding, which Plex uses with a Plex Pass.

Everything Plex keeps (libraries, watch history, settings) is in the `plex` folder of the state directory, so backing up that folder backs up Plex.

### Live

The **Live** page shows what's happening now, updating every five seconds:

- **Playing now:** who is watching what in Plex, how far through, on which device, and whether Plex plays it directly or transcodes it.
- **Transfers:** Transmission's download and upload speed, what's downloading and seeding, the overall ratio, and a chart of the last hour. The dashboard samples Transmission every five seconds in the background, so the chart has history as soon as you open the page; it starts empty after the dashboard restarts.
- **Downloading:** each active download named after its series episode or film, using Sonarr's and Radarr's queues, with progress, speed and time left. Downloads that Sonarr and Radarr didn't request keep their torrent name.
- **Recently watched:** Plex's watch history, newest first, with who watched it.

The Overview shows a compact version: current speeds and downloads, with the last hour's download speed drawn faintly behind them.

With Plex installed by setup, Live connects to it automatically. For a Plex server elsewhere, enter its address and token under **Settings → Plex** in the dashboard, or run setup with `--plex-url` (for example `--plex-url http://192.168.5.204:32400`) and `--set-plex-token`. To find the token, open Plex Web, choose any film or episode, open **⋯ → Get Info → View XML**, and copy the value after `X-Plex-Token=` in the address bar. The token stays private on the VM. Plex keeps its own watch history, but older entries may be pruned over time; Tautulli keeps a permanent record, so check how far back Live's history goes before retiring Tautulli.

### Discover

The **Library** page lists series with episodes coming up or missing, and films still to download. Switch a section to **All series** or **All films** to see everything in Sonarr or Radarr, with what each title takes up on disk. The bin button on a poster deletes that title: on its own it only removes the title from Sonarr or Radarr, which stop monitoring and downloading it, and its files stay where they are. Tick **Delete files too** to delete its folder from your media as well; that can't be undone.

The **Discover** page shows trending films and series, what's coming to cinemas, and what's new on streaming in your region, whether or not it's in your library. Titles you already have say **In library**; **Add** opens the Add page on that exact title with its options ready.

The lists come from [TMDB](https://www.themoviedb.org/), using MartinFlix's own TMDB API key, so Discover works without any setup. To use your own key instead, get a free one in your TMDB account under **Settings → API** (the **API Key**, or the longer **API Read Access Token**), then paste it under **Settings → Discover** in the dashboard (or run setup with `--set-tmdb-key`); it's stored privately on the VM. The same section hides the page, and chooses the country for the cinema and streaming lists, the UK by default (`--discover off` and `--discover-region US` from a terminal). The lists are cached for an hour.

### Backups

Every night at 01:00 the controller backs up each app's settings and data, keeping the last 14 plus one a week for 8 weeks. Choose the folder under **Settings → Backups**, or with `--backup-dir`, ideally a NAS share or another disk (for example `--backup-dir /mnt/martinflix/Backups`); each machine uses its own subfolder. To restore one, choose **Restore** beside it on the Backups page; `--restore` does the same from a terminal, and rebuilds a new machine from a backup. See [Backup and recovery](backups.md) for what each backup holds and how a restore works.

### Restart and update apps from the dashboard

Each card on the **Services** page has **Restart** and **Update** buttons, and the dashboard asks for a PIN before either runs. Setup asks you to choose the PIN (4 to 8 digits) and stores only a hash of it. To change it, use **Change PIN** in the dashboard's sidebar, which asks for the current PIN first. If you've forgotten it, rerun setup on the VM with `--change-pin`. Five wrong PINs lock restarts, updates, and PIN changes for five minutes.

The buttons are served by a separate **controller** container, the only part of the stack with Docker access. It has no published port, shares a private network with the dashboard alone, and checks the PIN itself, so the dashboard cannot restart or update anything without it. A **MartinFlix** section lists the dashboard and the controller. They can be restarted from there; they update together with MartinFlix, from **Settings**. The page reloads once the dashboard is back, and you stay signed in.

- **Restart** restarts the app. Restarting Gluetun also restarts Transmission, Prowlarr, FlareSolverr, and Bazarr afterwards, because they use its network connection.
- **Update** downloads the app's newest image. If there is one, the app is recreated with it, along with any apps on its network; your settings stay in place. Gluetun is pinned to a tested version, so its update arrives with a new MartinFlix version. Gluetun's card also has **Test VPN**: Transmission (or Prowlarr, or Gluetun itself) looks up its own public address and location through the VPN, and the dashboard compares it with your own connection's. It says whether downloads are protected and where they go out, or, if the VPN is down, why: a rejected NordVPN login, a server that won't complete the handshake, or a network that blocks the VPN. While the VPN is down, Gluetun blocks everything behind it, so nothing goes out unprotected.

The controller also reports each container's uptime, so every card shows how long it has been up.

Existing logins are preserved when you rerun the installer. Installations made before every app shared the dashboard password switch Transmission to the `admin` username and keep its old password; use **Change password** once to bring every app onto your password.

Transmission has no API for changing its own password, but it takes the shared password from its private file each time it starts. When you change your password, the dashboard asks the controller to restart Transmission as part of the change, so it takes the new password straight away; downloads pause briefly and resume on their own.

The dashboard, Sonarr, Radarr, Prowlarr, Transmission, and Bazarr publish on loopback by default. Pass `--dashboard-bind` with the host’s LAN IPv4 address to open them all from another machine. Every app has the shared login, and setup keeps each app on loopback until its login is in place. Gluetun and FlareSolverr have no web page.

### Start from scratch

Run your installer command again and add `--reset`. Include the state directory, LAN address, media path, and optional services you want for the new installation. Run it with `--check` as well first: the check validates the new options, Docker, directories, and ports without stopping or archiving anything. If the new options drop anything the current installation uses, such as its LAN address, media directory, or download apps, the check lists those changes and prints the options that would keep them. Then run it without `--check` and type `RESET` at the prompt. Setup validates every option before it asks, so a mistake never leaves you with a stopped stack. An installation still in the older default folder, `~/.local/state/martinflix-first-run`, is reset into the current default, `~/.local/state/martinflix`, unless you pass `--state-dir`. Its archive stays in the old folder. Setup stops the old stack, archives its app databases, configuration, and credentials in a private `reset-backup-*` directory inside the state directory, then creates a fresh installation. Your media files stay in place. Keep the archive private because it contains old credentials.

To run an isolated trial alongside another stack, use a separate state directory and different host ports:

```sh
docker run --rm -it --pull always -v /var/run/docker.sock:/var/run/docker.sock -v "$HOME:$HOME" -e HOME \
  ghcr.io/descalzi/martinflix:edge install \
  --state-dir ~/.local/state/martinflix-trial --media-path /mnt/media-trial \
  --dashboard-port 18765 --sonarr-port 18989 --radarr-port 17878
```

### Updates and settings

The controller checks for a newer MartinFlix image on the installation's channel a couple of minutes after it starts and then every six hours, by asking Docker to download it; the controller itself never reaches the internet. A new version shows on the Overview and on **Settings**, with the list of changes from GitHub. **Update now** asks for your PIN, then runs setup again from the new image in a container of its own, `…-updater`, because setup recreates the controller and the dashboard on the way. Settings shows setup's output as it goes; the dashboard restarts near the end and the page reloads by itself. If an update fails, the output says why and nothing after that step changed; fix the cause and update again, from Settings or from a terminal.

**Telegram.** MartinFlix can post to a Telegram chat when an episode or film is ready to watch (upgrades included) and when a series or film is added, with its poster, in the same format for both. Several episodes imported together, such as a season pack, become one message. To set it up:

1. In Telegram, message **@BotFather**, send `/newbot` and follow its questions. It replies with the bot token, such as `123456789:AAH…`.
2. Send your new bot any message, or add it to a group and say hello there.
3. In the dashboard, open **Settings → Telegram**, switch on **Post to Telegram**, paste the token, choose **Find chats** and pick the chat, then **Save changes**. Or add `--set-telegram` to setup, which asks for the token and lists the chats.

Once saved, **Send a test message** checks it. Sonarr and Radarr get a webhook connection named MartinFlix, which tells the dashboard what happened; the dashboard sends the message. Connections you made yourself in Sonarr or Radarr, including their own Telegram ones, are left as they are, so remove those if you don't want two messages.

**Settings** also changes Telegram, Discover (on or off, country, your own TMDB key), Plex (the server name, or the address and token of a Plex elsewhere), the backup folder, the VPN exit, protocol and service credentials, and the release channel. Saving runs setup the same way, with your PIN, so the change is checked and applied exactly as from a terminal and only the apps it affects restart. Secrets reach setup in a private file that it deletes as soon as it has read it.

The **edge** channel gets every change pushed to `main`; **stable** gets versions tagged `v1.2.0` and so on. A new installation follows the channel of the image you ran (`:edge` or `:stable`); switch under **Settings → Updates**, or with `--channel`.

### Update an existing installation

MartinFlix updates from the dashboard: see [Updates and settings](#updates-and-settings). To change what's installed (add apps, move the address or ports), run setup with `update` in place of `install`, plus the options that change. Add `--state-dir` for a custom location. `update` fails instead of creating a new installation if it cannot find one.

Setup remembers the dashboard address, ports, media directory, VPN exit, and download services. An update reuses them, and any flag you pass changes that one setting, for example `--enable-prowlarr` to add Prowlarr or `--dashboard-port 18765` to move the dashboard. Installs created before setup saved the address and ports recover them from their running containers. If those containers are stopped, pass `--dashboard-bind` again if you use LAN access. The download route can change in either direction with `--download-network`. Setup repoints Transmission’s connection and download path mapping in Sonarr and Radarr, Prowlarr’s address in both apps, and a FlareSolverr proxy in Prowlarr, if it uses the address setup printed. Before an update, setup lists what will change from the current installation. In the [setup wizard](https://descalzi.github.io/martinflix/), choose **Update or change an existing installation**: its **Changes** step starts with everything as it is, and only what you change goes into the command.

Every run downloads the latest image for each app, so an update also updates Sonarr, Radarr, and the download apps; the dashboard and controller run from the MartinFlix image setup came from. Containers whose image changed are recreated. Older images stay on disk; remove unused ones with `docker image prune` when you’re happy with the update. Bind-mounted settings, databases, credentials, and media persist. App data for these installs is under the state directory and each app normally mounts its subdirectory at `/config`. References to `/var/lib` in the inventory and existing-host guides describe the older reference deployment. The project name follows the state directory. The installer preserves app configurations and the password set on first sign-in, refreshes the private copies of the Arr keys, and verifies both connections again. The dashboard has no Docker socket.

## Media and downloads

Use a dedicated directory for your media. It can be a mounted NAS share or a directory on the VM. Set up the mount first if you use a share, and make sure your normal account can write there. The installer creates missing `TV Shows`, `Movies`, and `downloads` directories inside it. With Transmission it also creates `downloads/complete/sonarr`, `downloads/complete/radarr` and `downloads/incomplete`, so Sonarr and Radarr find their download folders before the first torrent finishes. Downloads and the library share one mount, so imports can use hard links instead of copies.

For library folders without the download services, pass only `--media-path`. To install the download services too, run the following in a terminal. Replace the sample path and use your usual `--dashboard-bind` option if you access the dashboard from another device.

```sh
docker run --rm -it --pull always -v /var/run/docker.sock:/var/run/docker.sock -v "$HOME:$HOME" -e HOME \
  ghcr.io/descalzi/martinflix:edge install --media-path /mnt/media --enable-downloads --check
docker run --rm -it --pull always -v /var/run/docker.sock:/var/run/docker.sock -v "$HOME:$HOME" -e HOME \
  ghcr.io/descalzi/martinflix:edge install --media-path /mnt/media --enable-downloads
```

The VPN option requires `/dev/net/tun` and your NordVPN **service credentials**, which aren’t your Nord Account email and password. In your [Nord Account](https://my.nordaccount.com/dashboard/nordvpn/manual-configuration/), open NordVPN → **Set up NordVPN manually**, enter the code NordVPN emails you, and copy the username and password from the **Service credentials** tab. [NordVPN’s guide](https://support.nordvpn.com/hc/en-us/articles/19685514639633-How-to-find-your-service-credentials-for-manual-NordVPN-setup) has screenshots. The installer prompts for the credentials without echoing them and saves them in private files in the state directory; replace them later under **Settings → VPN**. Gluetun uses NordVPN and defaults to Prague, matching the reference Compose file. Pass `--enable-vpn` for a standalone VPN gateway. Use `--vpn-city Prague` or a supported `--vpn-country` to choose the exit. Before connecting, setup downloads NordVPN’s current server list into the state directory, and Gluetun refreshes it daily, so an out-of-date list built into the image can’t send it to a retired server. If your network blocks VPN traffic over UDP, add `--vpn-protocol tcp`; setup remembers the choice. If a server rejects the login (`AUTH_FAILED`), Gluetun moves on to another server in the same city instead of retrying the one that refused it. If every attempt is rejected, setup names the servers it tried and keeps your saved credentials, because NordVPN also refuses logins when the account is at its device limit. Stop VPN connections you no longer use before you rerun it. VPN-backed Transmission, Prowlarr, and FlareSolverr share Gluetun’s network and wait for its health check. If you explicitly choose `--download-network direct`, those three services use the normal Docker network. Existing download routes are retained on rerun. Their web pages use ports 9091 and 9696 by default, on the same address as the dashboard. Sign in to both with `admin` and your dashboard password.

- Choose **MartinFlix HD (720p/1080p)** when adding titles. The installer creates the profile from the reference host’s allowed qualities and upgrade behavior. Existing titles keep their assigned profiles.
- Transmission starts with the reference host’s settings:
  - It stops seeding as soon as a download finishes (ratio limit 0).
  - It requires encryption, uses µTP and local peer discovery, and allows 75 peers per torrent.
  - It marks its traffic as low priority.
  - It blocks known bad peers with the Naunter blocklist, refreshed nightly.
  - Unfinished downloads stay in `downloads/incomplete`.

  Installations created before these defaults get the same choices applied once. Changes you make later in Transmission are kept.
- Transmission accepts peers on port 51155 (`--transmission-peer-port` to change it). With direct downloads the port is published on every address, so forward it on your router if you want incoming connections. Behind the VPN it isn’t published, because NordVPN doesn’t forward ports.
- Sonarr and Radarr use separate `sonarr` and `radarr` Transmission categories and map Transmission’s `/downloads` path to the shared `/data/downloads` folder for imports.
- Prowlarr is registered with both library apps using Full Sync, tagged as on the reference host: Sonarr gets the indexers tagged `movies` or `series`, Radarr those tagged `movies`. Prowlarr gives an app only the indexers that share one of its tags, so **tag any indexer you add yourself** `movies`, `series` or both, or it reaches neither app. When FlareSolverr is installed, setup adds it as Prowlarr's proxy with the same two tags, so it serves every tagged indexer and gets them past Cloudflare's browser check. With Transmission installed, Prowlarr also gets Transmission as its download client, with the `prowlarr` category, so a release found in Prowlarr's own search can be sent straight to it; its login follows dashboard password changes. Add your own indexers in Prowlarr.

### Subtitles with Bazarr

Add `--enable-bazarr` (with `--media-path`) to install Bazarr on port 6767. It uses the same network route as the download apps and sees the media directory at `/data`, the same as Sonarr and Radarr, so no path mappings are needed. Setup connects it to Sonarr and Radarr and gives it the shared `admin` login. On first install it applies the reference host's choices:

- **Providers:** Supersubtitles, YIFY Subtitles, TVsubtitles, Subtitulamos.tv, OpenSubtitles.com, and subtitles already embedded in the video.
- **Languages:** English, French, Portuguese (Brazil), Spanish and Spanish (Latino), with the two Spanish variants treated as equal.
- **Profiles:** "All Languages" (Latino Spanish, Brazilian Portuguese, English, French), used by default for new series and films, and "Not-English" (Brazilian Portuguese, Latino Spanish).
- **Subtitle handling:** subtitles are cleaned of hearing-impaired tags, common errors and formatting tags, and timed to the video with subsync.
- **Upgrades:** better subtitles are looked for over 20 days, once every 24 hours.
- **Sync:** Sonarr and Radarr are synced every 180 minutes.

OpenSubtitles.com needs an account, so setup asks for its username and password in the terminal. Leave the username blank to skip it; the other providers still work, and you can add the login later under Bazarr's **Settings → Providers**. Later changes you make in Bazarr are kept.

Select individual apps with `--download-client transmission`, `--enable-prowlarr`, `--enable-flaresolverr`, and `--enable-bazarr`. Prowlarr can run on its own. FlareSolverr requires Prowlarr and follows its network route. Only Transmission requires a media path. The older `--enable-downloads` flag still selects Transmission, Prowlarr, and FlareSolverr.

The first run with Prowlarr adds eight public indexers from the reference setup using Prowlarr’s built-in definitions. They’re saved enabled, without Prowlarr’s connection test, so an indexer that is down during setup still gets added; Prowlarr’s health checks then show any that keep failing, and you can disable those. Each gets a site address (its base URL): the reference host's (such as `https://1337x.to/`) where Prowlarr still offers it, otherwise the first Prowlarr lists, as its own Add dialog would. Each gets the reference host's tags too: `movies`, `series` or both, by what the site carries; TorrentDownloads carries only a books tag there, so here it has none and is left for searching in Prowlarr itself. Installs from earlier setups get the addresses, tags and FlareSolverr's tags once on their next update, and the `flaresolverr` tag those setups used goes. Setup reports any unavailable definitions. Installs whose indexers an earlier setup left disabled get them enabled once on the next update. Existing indexers are preserved, and later reruns respect indexers you remove.

The media path and enabled download services are remembered when you rerun setup. The installer fills in missing connections and preserves existing named records, including any edits you make in the apps. A different media root requires a separate installation or a planned storage migration.

The dashboard checks whether the configured services respond over the Compose network. Full Docker status collection and additional download clients are separate installer stages. To request titles, use the dashboard’s **Add** page instead of a separate request app. The existing-host deployment has its own Compose files, status collector, and recovery process.
