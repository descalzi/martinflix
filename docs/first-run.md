# First-run installer

Start with a Linux host and an account that can run Docker Engine and Docker Compose. The installer uses Python 3.9+ and its standard library. If Docker is missing, install [Docker Engine and the Compose plugin](https://docs.docker.com/engine/install/) for your distribution and confirm `docker info` works as your normal user. See [Prepare the VM](../README.md#1-prepare-the-vm) if Python is missing or too old.

From the checkout, run:

```sh
python3 deploy/bootstrap/install.py --media-path /mnt/media --check
python3 deploy/bootstrap/install.py --media-path /mnt/media
```

Replace `/mnt/media` with your media directory. New installations and resets need one, because Sonarr and Radarr file series and films there; installations made before this keep working without one until you add it.

The check verifies the Python and Linux environment, Docker Engine and Compose, access to the local engine, storage permissions, and service ports. It creates no directories, pulls no images, and starts no containers.

| If the check says… | What to do |
| --- | --- |
| Docker or Compose is missing | Follow the [Docker installation instructions](https://docs.docker.com/engine/install/) and rerun the check. |
| Docker Engine is unavailable | Follow the start command printed for your Docker installation, then run `docker info`. |
| Your user cannot access Docker | Follow [Docker’s Linux access setup](https://docs.docker.com/engine/install/linux-postinstall/), sign out and back in, and rerun the check as your normal user. |
| A port is already in use | Use the flag named in the error with a free port, such as `--dashboard-port 18765`. Keep that flag in your install command. |
| A directory is unwritable or has unexpected permissions | Choose a private, writable directory with `--state-dir`. |
| An image download or build fails | Check the VM’s internet connection and Docker storage, then rerun with the same options. Image downloads are checked during installation. |

New installs store app data in `~/.local/state/martinflix` by default. Rerunning an earlier install reuses its existing `~/.local/state/martinflix-first-run` directory and Docker project. Continue passing the same `--state-dir` for an existing custom path. It starts Sonarr and Radarr, waits for their health checks, reads the keys generated by the apps, and starts the dashboard with private copies of those keys. It checks that the dashboard can read both libraries. Fresh libraries appear empty until you add titles.

The installer adds Sonarr’s enabled **Bad Stuff** release profile from the reference setup. It excludes releases whose titles match `MeGusta`, `scr`, `exe`, or `ETHEL`. Setup also seeds Sonarr’s indexer defaults once, using a minimum age of 120 minutes and a maximum size of 3,000 MB. It preserves any existing nonzero values and leaves later edits in place.

Radarr gets **No OPUS** and **No HEVC**, both disabled to match the reference setup. You can enable either profile in Radarr to filter titles that match `Opus` or `HEVC` before download. Setup preserves existing release profiles with matching names in both apps.

New Radarr installations start with a maximum release size of 4,500 MB, an availability delay of 1 day, and an RSS sync interval of 120 minutes. Rerunning setup preserves your Radarr indexer settings.

The installer finishes with an **Open your dashboard** section. Sign in as `admin` using the temporary password shown by the command in that section. Sonarr, Radarr, Prowlarr, Transmission, and Bazarr use the username `admin` and the same temporary password. When you set your password on first sign-in or use **Change password** in the dashboard, MartinFlix updates every app, including the Transmission connection inside Sonarr and Radarr. The apps need to be running. If one can’t be reached, the dashboard keeps its current password; submit the same new password again once the app is back. The dashboard stores the chosen password as a salted hash in the private `dashboard-auth` directory.

Existing logins are preserved when you rerun the installer. Installations made before every app shared the dashboard password switch Transmission to the `admin` username and keep its old password; use **Change password** once to bring every app onto your password.

Transmission has no API for changing its own password, so a small `transmission-auth` container applies password changes. It shares Transmission’s process namespace, has no network or capabilities, and makes Transmission reload its settings without stopping downloads.

The dashboard, Sonarr, Radarr, Prowlarr, Transmission, and Bazarr publish on loopback by default. Pass `--dashboard-bind` with the host’s LAN IPv4 address to open them all from another machine. Every app has the shared login, and setup keeps each app on loopback until its login is in place. Gluetun and FlareSolverr have no web page.

### Start from scratch

Run your installer command again and add `--reset`. Include the state directory, LAN address, media path, and optional services you want for the new installation. Run it with `--check` as well first: the check validates the new options, Docker, directories, and ports without stopping or archiving anything. If the new options drop anything the current installation uses, such as its LAN address, media directory, or download apps, the check lists those changes and prints the options that would keep them. Then run it without `--check` and type `RESET` at the prompt. Setup validates every option before it asks, so a mistake never leaves you with a stopped stack. An installation still in the older default folder, `~/.local/state/martinflix-first-run`, is reset into the current default, `~/.local/state/martinflix`, unless you pass `--state-dir`. Its archive stays in the old folder. Setup stops the old stack, archives its app databases, configuration, and credentials in a private `reset-backup-*` directory inside the state directory, then creates a fresh installation. Your media files stay in place. Keep the archive private because it contains old credentials.

To run an isolated trial alongside another stack, use a separate state directory and different host ports:

```sh
python3 deploy/bootstrap/install.py \
  --state-dir ~/.local/state/martinflix-trial --media-path /mnt/media-trial \
  --dashboard-port 18765 --sonarr-port 18989 --radarr-port 17878
```

### Update an existing installation

From your checkout, run `git pull --ff-only`, then `python3 deploy/bootstrap/install.py --update --check` and `python3 deploy/bootstrap/install.py --update`. Add `--state-dir` for a custom location. `--update` fails instead of creating a new installation if it cannot find one.

Setup remembers the dashboard address, ports, media directory, VPN exit, and download services. An update reuses them, and any flag you pass changes that one setting, for example `--enable-prowlarr` to add Prowlarr or `--dashboard-port 18765` to move the dashboard. Installs created before setup saved the address and ports recover them from their running containers. If those containers are stopped, pass `--dashboard-bind` again if you use LAN access. The download route can change in either direction with `--download-network`. Setup repoints Transmission’s connection and download path mapping in Sonarr and Radarr, Prowlarr’s address in both apps, and a FlareSolverr proxy in Prowlarr, if it uses the address setup printed. Before an update, setup lists what will change from the current installation. In the [setup wizard](https://descalzi.github.io/martinflix/), choose **Update or change an existing installation**: its **Changes** step starts with everything as it is, and only what you change goes into the command.

Every run downloads the latest image for each app and rebuilds the dashboard on a fresh Python base image, so an update also updates Sonarr, Radarr, and the download apps. Containers whose image changed are recreated. Older images stay on disk; remove unused ones with `docker image prune` when you’re happy with the update. Bind-mounted settings, databases, credentials, and media persist. App data for these installs is under the state directory and each app normally mounts its subdirectory at `/config`. References to `/var/lib` in the inventory and existing-host guides describe the older reference deployment. The project name follows the state directory. The installer preserves app configurations and the password set on first sign-in, refreshes the private copies of the Arr keys, and verifies both connections again. Keep the application data and password files outside the checkout. The dashboard has no Docker socket.

## Media and downloads

Use a dedicated directory for your media. It can be a mounted NAS share or a directory on the VM. Set up the mount first if you use a share, and make sure your normal account can write there. The installer creates missing `TV Shows`, `Movies`, and `downloads` directories inside it. With Transmission it also creates `downloads/complete/sonarr`, `downloads/complete/radarr` and `downloads/incomplete`, so Sonarr and Radarr find their download folders before the first torrent finishes. Downloads and the library share one mount, so imports can use hard links instead of copies.

For library folders without the download services, pass only `--media-path`. To install the download services too, run the following in a terminal. Replace the sample path and use your usual `--dashboard-bind` option if you access the dashboard from another device.

```sh
python3 deploy/bootstrap/install.py --media-path "/mnt/media" --enable-downloads --check
python3 deploy/bootstrap/install.py --media-path "/mnt/media" --enable-downloads
```

The VPN option requires `/dev/net/tun` and your NordVPN **service credentials**, which aren’t your Nord Account email and password. In your [Nord Account](https://my.nordaccount.com/dashboard/nordvpn/manual-configuration/), open NordVPN → **Set up NordVPN manually**, enter the code NordVPN emails you, and copy the username and password from the **Service credentials** tab. [NordVPN’s guide](https://support.nordvpn.com/hc/en-us/articles/19685514639633-How-to-find-your-service-credentials-for-manual-NordVPN-setup) has screenshots. The installer prompts for the credentials without echoing them and saves them in private files outside the repo. Gluetun uses NordVPN and defaults to Prague, matching the reference Compose file. Pass `--enable-vpn` for a standalone VPN gateway. Use `--vpn-city Prague` or a supported `--vpn-country` to choose the exit. Before connecting, setup downloads NordVPN’s current server list into the state directory, and Gluetun refreshes it daily, so an out-of-date list built into the image can’t send it to a retired server. If your network blocks VPN traffic over UDP, add `--vpn-protocol tcp`; setup remembers the choice. If a server rejects the login (`AUTH_FAILED`), Gluetun moves on to another server in the same city instead of retrying the one that refused it. If every attempt is rejected, setup names the servers it tried and keeps your saved credentials, because NordVPN also refuses logins when the account is at its device limit. Stop VPN connections you no longer use before you rerun it. VPN-backed Transmission, Prowlarr, and FlareSolverr share Gluetun’s network and wait for its health check. If you explicitly choose `--download-network direct`, those three services use the normal Docker network. Existing download routes are retained on rerun. Their web pages use ports 9091 and 9696 by default, on the same address as the dashboard. Sign in to both with `admin` and your dashboard password.

- Choose **MartinFlix HD (720p/1080p)** when adding titles. The installer creates the profile from the reference host’s allowed qualities and upgrade behavior. Existing titles keep their assigned profiles.
- Transmission starts with the reference host’s settings:
  - It stops seeding as soon as a download finishes (ratio limit 0).
  - It requires encryption, uses µTP and local peer discovery, and allows 75 peers per torrent.
  - It marks its traffic as low priority.
  - It blocks known bad peers with the Naunter blocklist, refreshed nightly.
  - Unfinished downloads stay in `downloads/incomplete`.

  Installations created before these defaults get the same choices applied once. Changes you make later in Transmission are kept.
- Transmission accepts peers on port 51155 (`--transmission-peer-port` to change it). With direct downloads the port is published on every address, so forward it on your router if you want incoming connections. Behind the VPN it isn’t published, because NordVPN doesn’t forward ports.
- Sonarr and Radarr use separate `sonarr` and `radarr` Transmission categories and map Transmission’s `/downloads` path to the shared `/data/downloads` folder for imports.
- Prowlarr is registered with both library apps using Full Sync. Add your own indexers in Prowlarr. When FlareSolverr is installed, setup adds it as Prowlarr’s proxy for the `flaresolverr` tag. Add that tag to any indexer that fails behind Cloudflare’s browser check. Setup leaves indexer credentials and searches under your control.

### Subtitles with Bazarr

Add `--enable-bazarr` (with `--media-path`) to install Bazarr on port 6767. It uses the same network route as the download apps and sees the media directory at `/data`, the same as Sonarr and Radarr, so no path mappings are needed. Setup connects it to Sonarr and Radarr and gives it the shared `admin` login. On first install it applies the reference host's choices:

- **Providers:** Supersubtitles, YIFY Subtitles, TVsubtitles, Subtitulamos.tv, OpenSubtitles.com, and subtitles already embedded in the video.
- **Languages:** English, French, Portuguese (Brazil), Spanish and Spanish (Latino), with the two Spanish variants treated as equal.
- **Profiles:** "All Languages" (Latino Spanish, Brazilian Portuguese, English, French), used by default for new series and films, and "Not-English" (Brazilian Portuguese, Latino Spanish).
- **Subtitle handling:** subtitles are cleaned of hearing-impaired tags, common errors and formatting tags, and timed to the video with subsync.
- **Upgrades:** better subtitles are looked for over 20 days, once every 24 hours.
- **Sync:** Sonarr and Radarr are synced every 180 minutes.

OpenSubtitles.com needs an account, so setup asks for its username and password in the terminal. Leave the username blank to skip it; the other providers still work, and you can add the login later under Bazarr's **Settings → Providers**. Later changes you make in Bazarr are kept.

Select individual apps with `--download-client transmission`, `--enable-prowlarr`, `--enable-flaresolverr`, and `--enable-bazarr`. Prowlarr can run on its own. FlareSolverr requires Prowlarr and follows its network route. Only Transmission requires a media path. The older `--enable-downloads` flag still selects Transmission, Prowlarr, and FlareSolverr.

The first run with Prowlarr adds eight public indexers from the reference setup using Prowlarr’s built-in definitions. They’re saved enabled, without Prowlarr’s connection test, so an indexer that is down during setup still gets added; Prowlarr’s health checks then show any that keep failing, and you can disable those. 1337x gets the `flaresolverr` tag. Setup reports any unavailable definitions. Installs whose indexers an earlier setup left disabled get them enabled once on the next update. Existing indexers are preserved, and later reruns respect indexers you remove.

The media path and enabled download services are remembered when you rerun setup. The installer fills in missing connections and preserves existing named records, including any edits you make in the apps. A different media root requires a separate installation or a planned storage migration.

The dashboard checks whether the configured services respond over the Compose network. Full Docker status collection and additional download clients are separate installer stages. To request titles, use the dashboard’s **Add** page instead of a separate request app. The existing-host deployment has its own Compose files, status collector, and recovery process.
