# First-run installer

Start with a Linux host and an account that can run Docker Engine and Docker Compose. The installer uses Python 3.9+ and its standard library. If Docker is missing, install [Docker Engine and the Compose plugin](https://docs.docker.com/engine/install/) for your distribution and confirm `docker info` works as your normal user. See [Prepare the VM](../README.md#1-prepare-the-vm) if Python is missing or too old.

From the checkout, run:

```sh
python3 deploy/bootstrap/install.py --check
python3 deploy/bootstrap/install.py
```

The check verifies the Python and Linux environment, Docker Engine and Compose, access to the local engine, storage permissions, and service ports. It creates no directories, pulls no images, and starts no containers.

| If the check says… | What to do |
| --- | --- |
| Docker or Compose is missing | Follow the [Docker installation instructions](https://docs.docker.com/engine/install/) and rerun the check. |
| Docker Engine is unavailable | Follow the start command printed for your Docker installation, then run `docker info`. |
| Your user cannot access Docker | Follow [Docker’s Linux access setup](https://docs.docker.com/engine/install/linux-postinstall/), sign out and back in, and rerun the check as your normal user. |
| A port is already in use | Use the flag named in the error with a free port, such as `--dashboard-port 18765`. Keep that flag in your install command. |
| A directory is unwritable or has unexpected permissions | Choose a private, writable directory with `--state-dir`. |
| An image download or build fails | Check the VM’s internet connection and Docker storage, then rerun with the same options. Image downloads are checked during installation. |

New installs store app data in `~/.local/state/martinflix` by default. Rerunning an earlier install reuses its existing `~/.local/state/martinflix-first-run` directory and Docker project. Continue passing the same `--state-dir` for an existing custom path. It starts Sonarr and Radarr, waits for their health checks, reads the keys generated by the apps, and starts the dashboard with private copies of those keys. It checks that the dashboard can read both libraries. Fresh libraries appear empty until you add titles.

The installer adds Sonarr’s enabled **Bad Stuff** release profile from the reference setup. It excludes releases whose titles match `MeGusta`, `scr`, `exe`, or `ETHEL`. If a profile with that name already exists, setup leaves its settings in place. Release profiles filter titles before download and cannot inspect the files inside a release. Setup also seeds Sonarr’s indexer defaults once, using a minimum age of 120 minutes and a maximum size of 3,000 MB. It preserves any existing nonzero values and leaves later edits in place.

The installer finishes with an **Open your dashboard** section. Sign in as `admin` using the temporary password shown by the command in that section. The dashboard asks you to choose a password of at least eight characters, then sign in again. The temporary password stops working after the change. The chosen password is stored as a salted hash in the private `dashboard-auth` directory. Upgrading an earlier first-run installation prompts for this change once, using its existing generated password. All three services publish on loopback by default. Pass `--dashboard-bind` with the host’s LAN IPv4 address to publish the dashboard, Sonarr, and Radarr on that address. Open the URLs printed by setup and configure app authentication on first use. HTTP sends credentials unencrypted across the network. Prowlarr and Transmission remain on loopback.

To run an isolated trial alongside another stack, use a separate state directory and different host ports:

```sh
python3 deploy/bootstrap/install.py \
  --state-dir ~/.local/state/martinflix-trial \
  --dashboard-port 18765 --sonarr-port 18989 --radarr-port 17878
```

Rerun with the same arguments to resume setup. The project name follows the state directory. The installer preserves app configurations and the password set on first sign-in, refreshes the private copies of the Arr keys, and verifies both connections again. Keep the application data and password files outside the checkout. The dashboard has no Docker socket.

## Media and downloads

Use a dedicated directory for your media. It can be a mounted NAS share or a directory on the VM. Set up the mount first if you use a share, and make sure your normal account can write there. The installer creates missing `TV Shows`, `Movies`, and `downloads` directories inside it.

For library folders without the download services, pass only `--media-path`. To install the download services too, run the following in a terminal. Replace the sample path and use your usual `--dashboard-bind` option if you access the dashboard from another device.

```sh
python3 deploy/bootstrap/install.py --media-path "/mnt/media" --enable-downloads --check
python3 deploy/bootstrap/install.py --media-path "/mnt/media" --enable-downloads
```

The download option requires `/dev/net/tun` and [manual OpenVPN service credentials from your Nord Account](https://support.nordvpn.com/hc/en-us/articles/19685514639633-How-to-find-your-service-credentials-for-manual-NordVPN-setup). The installer prompts for the credentials without echoing them and saves them in private files outside the repo. Gluetun uses NordVPN and defaults to Prague, matching the reference Compose file. Transmission and Prowlarr share Gluetun’s network and wait for its health check. Their setup screens are on VM loopback at ports 9091 and 9696 by default. The installer prints how to retrieve the generated Transmission password.

- Choose **MartinFlix HD (720p/1080p)** when adding titles. The installer creates the profile from the reference host’s allowed qualities and upgrade behavior. Existing titles keep their assigned profiles.
- Sonarr and Radarr use separate `sonarr` and `radarr` Transmission categories and map Transmission’s `/downloads` path to the shared `/data/downloads` folder for imports.
- Prowlarr is registered with both library apps using Full Sync. Add your own indexers in Prowlarr. The installer does not import the reference host’s credentials or trigger searches.

The media path and enabled download services are remembered when you rerun setup. The installer fills in missing connections and preserves existing named records, including any edits you make in the apps. A different media root requires a separate installation or a planned storage migration.

The dashboard checks whether the configured services respond over the Compose network. Full Docker status collection, Seerr, Bazarr, and FlareSolverr are separate installer stages. The existing-host deployment has its own Compose files, status collector, and recovery process.
